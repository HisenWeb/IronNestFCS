## IronNestFCS Smart v1.1.8

### Reliable pending queue / 更可靠的等待队列

- Tasks that cannot be planned against the guns' current physical loading state now remain in the Pending queue instead of disappearing.
- A blocked task at the front of the queue no longer prevents later compatible tasks from being planned and executed.
- A task leaves Pending only after a concrete FirePlan has been accepted by the executor.
- Dispatch requests that arrive while a planning round is already running are preserved and replayed after the current round, avoiding a narrow missed-trigger race.

- 当前两门炮的实际装填状态无法执行某个任务时，该任务现在会继续保留在等待队列中，不再直接消失。
- 队首存在暂时无法执行的任务时，后面能够匹配当前炮况的任务仍然可以继续规划和执行。
- 只有具体 FirePlan 已经被执行器接受后，任务才会真正离开 Pending。
- 如果新的调度请求恰好发生在已有规划轮次运行期间，系统会保留这次触发并在当前轮结束后补跑，避免极窄窗口下漏掉新任务。

### Fast ammunition compatibility screening / 快速弹药兼容筛选

- Planner now checks the requested shell type against the shell already loaded or currently being loaded before opening the game's ballistic calculator.
- Fixed-charge maximum range is also screened before the expensive calculator interaction: C1 through C6 use 5 km steps as maximum-range ceilings.
- Higher charges remain valid for shorter targets; for example C6 is not rejected simply because the target is within 5 km.
- Incompatible candidates are skipped immediately, which prevents old Pending tasks from repeatedly spending several seconds driving the game's calculator UI.

- Planner 现在会先检查任务弹种是否与炮内已装弹种或当前装填事务的弹种一致，再决定是否进入游戏弹道计算器。
- 固定装药的最大射程也会在昂贵的弹道计算前快速筛选：C1～C6 按每档 5 km 作为最大射程上限。
- 高装药仍然可以用于更近目标，例如 C6 不会因为目标在 5 km 以内而被错误排除。
- 不兼容的炮位候选会立即跳过，避免旧 Pending 任务反复驱动游戏弹道计算器 UI、造成明显等待。

### Lightweight Pending hints / 轻量等待提示

- The HUD now adds a short reason to Pending tasks when useful, such as `shell mismatch` or `charge range insufficient`.
- When one gun has the correct shell but its current charge cannot reach the target, the HUD reports the range limitation instead of the more confusing generic ammunition mismatch message.
- These hints are display-only; they do not participate in scheduling or change task priority.

- HUD 会在有必要时给等待任务追加一个简短原因，例如“弹种不匹配”或“装药射程不足”。
- 如果至少有一门炮弹种正确、只是当前装药够不到目标，HUD 会优先显示“装药射程不足”，不再给出容易误解的笼统“弹药不匹配”。
- 这些提示只用于显示，不参与调度，也不会改变任务优先级。

### Event-driven scheduling and UI polish / 事件驱动调度与界面修正

- Pending re-planning remains event-driven: new task submission, gun-slot release, and focus resume can trigger another planning round without per-frame Pending polling.
- The initial firing-order status now binds the game language before caching its text, fixing an English `Firing order: not committed (reset)` line appearing inside the Chinese HUD.

- Pending 重规划保持事件驱动：新任务提交、炮位释放以及游戏窗口恢复焦点都可以触发新的规划轮次，不需要每帧轮询等待队列。
- 初始射击顺序状态现在会先完成游戏语言识别再缓存文本，修复中文版 HUD 中偶尔出现英文 `Firing order: not committed (reset)` 的问题。

### Notes / 说明

- F9 still resets TaskSystem planning and queued tasks, not persistent physical loading already accepted by the Host.
- An incompatible task can intentionally remain Pending until the physical gun state changes or the player resets/replans with F9.
- Existing FirePlans already accepted by the executor are not rewritten by later Pending tasks.

- F9 仍然只重置 TaskSystem 的计划和任务队列，不会抹掉已经被 Host 接受的持久物理装填。
- 不兼容任务会有意保留在 Pending，直到实际炮况发生变化，或玩家按 F9 放弃当前任务并重新规划。
- 已经被执行器接受的 FirePlan 不会被后续 Pending 任务改写。
