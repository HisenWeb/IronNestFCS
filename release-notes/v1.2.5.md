## IronNestFCS Smart v1.2.5

### Physical ammunition UI sync / 实体弹药台同步

- Ammunition buttons now follow the shell punchcards that are actually present on the physical Requisition Console instead of assuming every `BulletType` is available.
- The FCS rescans the physical requisition deck at runtime and refreshes the ammo UI automatically after the available shell set becomes stable.
- Startup no longer treats the short period before punchcards finish spawning as an authoritative empty ammunition list.
- Existing A/B ammo-button layout and selection fallback behavior are preserved; if the selected shell disappears, Smart falls back to HE when available, otherwise to the first available shell.
- Temporary requisition diagnostic probes used during development are not included in the release build.

- 弹种按钮现在直接跟随实体 Requisition Console 上实际存在的炮弹 Punchcard，不再默认 `BulletType` 中的所有弹种都可用。
- FCS 会在运行时重新扫描实体弹药台，并在可用弹种集合稳定后自动刷新弹种 UI。
- 游戏启动时 Punchcard 尚未生成完成的短暂阶段，不再被误判为“当前没有可用弹种”。
- 现有 A/B 弹种按钮布局与选择回退逻辑保持不变；如果当前选择的弹种消失，Smart 会优先回退到 HE，否则选择当前第一个可用弹种。
- 开发阶段使用的征用台诊断探针不会进入正式发布包。

### Pending order with charge-resource protection / 保留装药资源的 Pending 顺序

- Dual-gun matching still maximizes the number of tasks that can be admitted in the current physical state.
- Scarce charge/range capability remains protected first: a short-range task should not consume a higher-charge gun when that would prevent a farther task from using the range it actually needs.
- Once two candidate assignments have the same cardinality and the same charge fit, earlier Pending tasks now win before ETA or azimuth soft costs are considered.
- ETA and azimuth are therefore limited to choosing the better Left/Right mapping for an already-equivalent task set; they no longer reorder targets merely because a later task is faster or closer to the current turret direction.
- Later Pending tasks can still bypass an older task when the older task has no compatible Task × Gun edge, or when charge/range constraints make a different maximum-cardinality assignment necessary.
- The final azimuth tie-break uses the same signed-bearing conversion as the canonical turret slew estimator.

- 双炮 Matcher 仍然首先尽量让当前可用炮位接到最多任务。
- 装药 / 射程资源保护继续优先：短程任务不应占用更高装药炮位，从而让真正需要该射程能力的远程任务失去可用炮位。
- 当两个候选方案的匹配数量和装药适配程度相同时，现在会先按 Pending 提交顺序选择更早的任务，再比较 ETA 或方位角软成本。
- 因此 ETA 与方位角只负责在同等任务集合中选择更好的 Left / Right 分配，不再因为后提交任务更快或更接近当前炮塔方向就改变玩家的目标顺序。
- 如果较早任务当前没有任何兼容的 Task × Gun 边，或装药 / 射程约束要求另一组最大匹配方案，后面的兼容任务仍然可以正常越过。
- 最后的方位角 tie-break 现在与炮塔转向估算使用同一套带符号方位转换。

### Notes / 说明

- F9 semantics are unchanged: F9 resets TaskSystem planning, not persistent physical loading reality.
- FirePlan execution, physical-shot settlement, Auto Fire, Max Charge, selected-only ballistic materialization and the existing two-gun matching architecture remain intact.
- The requisition-deck change was project-build and basic in-game tested before merge. The matcher change was checked against regression scenarios covering initial-state admission, constrained loaded states, C1/C2 range protection, blocked Pending bypass and edge-exclusion rematching.

- F9 语义保持不变：F9 重置 TaskSystem 计划，不会抹掉持续存在的真实装填过程。
- FirePlan 执行、实际击发结算、Auto Fire、Max Charge、selected-only 弹道实体化以及现有双炮全局匹配架构保持不变。
- 实体弹药台同步功能在合入前已完成项目构建与基础实机测试；Matcher 调整已覆盖初始态接单、受限实装状态、C1/C2 射程资源保护、Blocked Pending 越过以及排除边后的 rematch 等回归场景。
